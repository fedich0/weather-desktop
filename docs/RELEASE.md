# Публикация Weather Desktop

## Исходники на GitHub

1. Создайте пустой репозиторий `weather-desktop` в своём аккаунте. Не добавляйте второй README или другую лицензию при создании.
2. Загрузите содержимое папки проекта, включая скрытую `.github`. Удобно через GitHub Desktop: добавьте локальную папку, создайте репозиторий, сделайте commit и Publish repository. Это загрузка исходников; готовый бинарный релиз создаётся отдельно.
3. Убедитесь, что README отображается в корне, а Actions видит `Build and tests`.
4. Включите Private vulnerability reporting, если собираетесь принимать сообщения о безопасности, и уточните контакт в SECURITY.md.
5. Дождитесь успешных Linux/macOS jobs и изучите их логи. Workflow не был запущен при подготовке этого архива. Артефакты `local-test-*` предназначены для проверки, они не нотариально заверены.

В проект добавлена MIT. Она позволяет другим людям копировать, изменять и продавать производные версии с сохранением уведомления об авторстве и текста лицензии. Автор указан как FediCh; перед первой публикацией можно заменить на предпочитаемое имя в LICENSE, README и Info.plist. Если такие условия не подходят, выберите лицензию до публикации.

Помощь ChatGPT/Codex отмечена в README. Не обещайте уникальность AI-кода или независимый аудит, пока для этого нет оснований.

## Проверка на настоящем Mac

Запустите `bash scripts/check-macos.sh` из корня проекта. Скрипт проверяет C++ ядро с ASan/UBSan, собирает приложение и запускает AppKit-сценарий во временной копии. Для интерфейсного теста нужна активная графическая сессия. Тест использует отдельный домен `local.windowsnow.smoketest`; он удаляется после успешного выполнения.

Если тест аварийно прервался, этот тестовый домен можно удалить командой `defaults delete local.windowsnow.smoketest`.

Затем вручную откройте `build/Weather Desktop.app` и пройдите проверки:

- [ ] Снег и листья видны, оседают на видимых краях и осыпаются при перемещении/закрытии окна.
- [ ] Длительное изменение размеров окна, перекрытие другим окном, сворачивание и возвращение не вызывают сбоя.
- [ ] Все ползунки, пресеты, стеклянные кнопки и сохранение/возврат профиля работают.
- [ ] Отключение пола/накопления очищает прежний слой; повторное включение рисует новый без старого кэша.
- [ ] Слой пропускает клики. Настройки доступны с клавиатуры; элементы имеют понятные названия в VoiceOver.
- [ ] Reduce Transparency проверен после повторного запуска; текст читается на светлых и тёмных обоях.
- [ ] Пауза, повторный запуск, закрытие настроек, Dock и Cmd+Q ведут себя ожидаемо.
- [ ] Сон/пробуждение, блокировка/разблокировка и смена пользовательской сессии не оставляют активную анимацию в фоне.
- [ ] Подключение/отключение второго монитора, разные масштабы Retina, Spaces и полноэкранные приложения проверены.
- [ ] Обычный режим и Eco проработали хотя бы 30 минут; после нескольких массовых осыпаний память не растёт бесконечно.
- [ ] На чистой учётной записи проверены запуск и работа без лишних разрешений.
- [ ] После удаления приложение не остаётся работающим; настройки и резервные сборки удаляются по README.

Запишите результаты в VERIFICATION.md. Для нагрузки используйте Activity Monitor: 5 минут без приложения, 5 минут с закрытыми настройками в обычном режиме, 5 минут в Eco. Зафиксируйте CPU, память, Energy Impact, число экранов, разрешение и сезон. CPU/память сами по себе не измеряют автономность батареи. Не публикуйте неподтверждённый процент расхода заряда.

## Готовое приложение для скачивания

Локальные тестовые ZIP и DMG создаёт `bash scripts/package.sh`. ZIP содержит универсальный `.app` для arm64 и x86_64, локальную подпись и файл SHA-256. Это не проверка Apple.

Для обычного распространения вне App Store подготовьте Developer ID Application certificate через свой Apple Developer account, подпишите сборку и отправьте её Apple на notarization. Закрытые ключи и пароли не добавляйте в репозиторий или архив. Инструкции Apple:

- [Developer ID](https://developer.apple.com/developer-id/)
- [Notarizing macOS software before distribution](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)
- [Customizing the notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)

Пример для разработчика с уже установленным сертификатом и заранее созданным профилем Keychain `WeatherDesktopNotary`. Значение `YOUR NAME (TEAMID)` нужно заменить на название вашего сертификата. Секретов в примере нет:

```bash
bash scripts/build.sh --universal
codesign --force --options runtime --timestamp \
  --sign 'Developer ID Application: YOUR NAME (TEAMID)' 'build/Weather Desktop.app'
codesign --verify --strict --verbose=2 'build/Weather Desktop.app'
mkdir -p dist
ditto -c -k --sequesterRsrc --keepParent 'build/Weather Desktop.app' dist/WeatherDesktop-notary.zip
xcrun notarytool submit dist/WeatherDesktop-notary.zip \
  --keychain-profile WeatherDesktopNotary --wait
```

**Продолжайте только при статусе Accepted.** Если статус другой, получите лог отправки через `notarytool log`, исправьте причину, заново подпишите и отправьте. После Accepted:

```bash
xcrun stapler staple 'build/Weather Desktop.app'
xcrun stapler validate 'build/Weather Desktop.app'
spctl --assess --type execute --verbose=2 'build/Weather Desktop.app'
ditto -c -k --sequesterRsrc --keepParent 'build/Weather Desktop.app' dist/WeatherDesktop-0.9.0-rc.1.zip
shasum -a 256 dist/WeatherDesktop-0.9.0-rc.1.zip > dist/WeatherDesktop-0.9.0-rc.1.zip.sha256
```

После notarization не запускайте `package.sh` для этого релиза: он заново собирает приложение с локальной подписью. Публикуйте итоговый архив после stapling и соответствующую контрольную сумму. Проверьте скачивание и первый запуск через Gatekeeper на другом Mac/чистой учётной записи.

Подпись связывает бинарный файл с разработчиком; notarization включает автоматическую проверку Apple. Ни одна из них не заменяет тестирование функциональности или аудит исходников.

Первый выпуск оформляйте как GitHub **pre-release** с тегом `v0.9.0-rc.1`, результатами тестов, известными ограничениями и CHANGELOG. Стабильный 1.0 имеет смысл выпускать после закрытия этого списка и исправления найденных проблем. Номер версии и CFBundleVersion в Info.plist необходимо увеличивать для новых сборок.

После успешной сборки `scripts/package.sh` также создаёт тестовый DMG с приложением и ссылкой Applications. Готового DMG в исходном архиве нет. Для публичного DMG нужно отдельно выполнить подпись и notarization итогового образа по документации Apple; приведённый выше пример распространяет ZIP.
